## پولیش Premium V2 اندروید — ۲۳ نوامبر ۲۰۲۶

- **Design System مشترک:** فایل `JibikPremiumUi.kt` با کامپوننت‌های `JibikHero`، `JibikQuickAction`، `JibikSectionTitle` و `JibikSurfaceCard`؛ پس‌زمینه گرادیان‌ها به‌صورت برداری در Compose است و WebP جیبو/لوگو شفاف می‌ماند.
- **Home:** اولویت بصری موجودی و وضعیت مالی واقعی، دو کارت خلاصه ماه شمسی، سه اقدام سریع برای ثبت هزینه/درآمد/خرید چندقلمی، بودجه و آخرین تراکنش‌ها؛ دکمه شناور تکراری از صفحه خانه برداشته شد.
- **Transactions:** جایگزینی اسکرول ساده با `LazyColumn` و کلید تراکنش، فیلترهای هزینه/درآمد/انتقال، جست‌وجو و کارت‌های سازگار با متن و مبلغ طولانی.
- **Accounts:** کارت بزرگ مجموع موجودی واقعی و کنترل‌های کوتاه، معرفی اهداف پس‌انداز و کارت‌های حساب جمع‌وجورتر.
- **Reports و Budget:** هم‌سبکی کارت سبز شاخص؛ نمایش پرهزینه‌ترین دسته بر پایه تراکنش‌های همین ماه؛ پیام بودجه بدون لحن سرزنش‌کننده.
- **مستندات طراحی و QA:** [ANDROID_UI_SPEC_FA.md](ANDROID_UI_SPEC_FA.md).
- **کامیت‌های کلیدی:** `2ea34882`، `c5bc5be2`، `02c9b4e5`، `6c3c21b3`، `b0fcf549`، `b0b4ce99`. خطای import در کامپوننت جدید با `81a5483a` رفع شد.
- **Build کد Android موفق:** [GitHub Actions #45232403231](https://github.com/qashqaeii/Jibak/actions/runs/45232403231)؛ artifact با نام `Jibik-debug-apk` تولید شد (بسته حدود ۱۱.۳ مگابایت). Build مربوط به نسخه Debug است، نه نسخه آماده بازار.
- **هنوز تست نشده:** بررسی بصری روی گوشی واقعی، Screenshot Regression، TalkBack، Font Scale بالا، طول متن در همه سایزها؛ آماده انتشار تجاری نیست.

## آخرین وضعیت تأییدشده — Django و همگام‌سازی اولیه (۲۳ نوامبر ۲۰۲۶)

- نقشه راه اصلی **تغییر نکرده است**: Android Native Kotlin + Jetpack Compose، بک‌اند Django REST Framework + PostgreSQL، خانواده، همگام‌سازی و آماده‌سازی فروش اشتراک/کافه‌بازار.
- ساختار `backend/`، مدل‌های Household/Membership/FinancialAccount/LedgerTransaction، migration اولیه و endpointهای `/api/v1/households/`، `accounts/`، `transactions/` ایجاد شدند.
- تراکنش سرور با مبلغ صحیح **ریال**، scope خصوصی یا خانوادگی، کنترل نقش در سمت سرور، و کلید Idempotency ثبت می‌شود. اندروید فعلاً مبلغ صحیح **تومان** نگه می‌دارد؛ تبدیل دقیق در Sync push آینده الزامی است.
- `GET /api/v1/sync/pull/` یک feed اولیه با Cursor امضاشده، محدود به کاربر و ۵۰ تراکنش در صفحه ارائه می‌کند. این API هنوز **همگام‌سازی کامل دوطرفه** نیست.
- CI مستقل Django با PostgreSQL و تست‌های حریم خصوصی، کنترل مجوز، انتقال پول، Idempotency، Cursor و Pagination تنظیم شده است.
- [اجرای موفق Django CI با پوشش تست Sync](https://github.com/qashqaeii/Jibak/actions/runs/45229986618)؛ قبل از هر ادعای آمادگی انتشار، CI آخرین HEAD و تست‌های دستگاه باید دوباره بررسی شوند.
- خطای کامپایل Android در فرم هدف پس‌انداز (`KeyboardOptions`) با کامیت `09a4a9e7` اصلاح شد؛ [Android CI موفق](https://github.com/qashqaeii/Jibak/actions/runs/45229657769).

**هنوز انجام‌نشده:** سرویس OTP واقعی و توکن امن موبایل، دعوت و عضویت عملی بین دو گوشی، Sync push با Outbox و سازوکار تعارض، وصل‌کردن کلاینت اندروید به API، رمزنگاری و بکاپ امن، تسویه/قبوض، خرید فروشگاهی و تأیید رسید، Entitlement، تست ابزارهای واقعی و آماده‌سازی انتشار کافه‌بازار.

توجه: بخش‌های پیشین این سند تاریخچه هستند و وضعیت آخرین کد را نمایندگی نمی‌کنند.

## فاز اولیه

- پروژه Gradle شامل :app و :core:finance ایجاد شده است.
- Kotlin / Jetpack Compose و RTL فارسی، تم سبز تیره، کرم و نارنجی.
- خوش‌آمدگویی اولیه، داشبورد حساب، نمایش تراکنش‌ها، ثبت درآمد و هزینه، و تغییر سقف بودجه.
- تراکنش‌ها اکنون به‌صورت آفلاین در Room ذخیره می‌شوند و داده‌های SharedPreferences نسخه قبلی با کنترل صحت و بدون حذف نسخه قدیمی وارد می‌شوند؛ تنظیمات بودجه و آنبوردینگ فعلاً در SharedPreferences مانده‌اند. رمزنگاری دیتابیس هنوز تکمیل نشده است.
- منطق محاسبه مالی مستقل با تست‌های واحد: انتقال بین حساب‌ها دوباره به درآمد یا هزینه تبدیل نمی‌شود؛ خرید چندقلمی تنها یک هزینه ایجاد می‌کند.
- GitHub Actions برای build debug APK و آپلود artifact تنظیم شده است.

## گزارش پولیش UI/UX — ۲۳ نوامبر ۲۰۲۶

- صفحه‌های Home، Transactions، Budget، Welcome و پنجره‌های ثبت تراکنش/ویرایش بودجه بر اساس بازخورد تصاویر واقعی کاربر یکپارچه‌تر شدند؛ تم سبز جنگلی، کرم و نارنجی حفظ شد.
- `JibikVisuals.kt` یک کاراکتر برداری موقت جیبو و آیکون‌های مستقل از فونت/ایموجی را ارائه می‌کند. تصویر رسمی مورد تأیید کاربر هنوز باید به **WebP کم‌حجم** تبدیل و جایگزین شود.
- عنوان «موجودی کل» که به اشتباه برای باقی‌مانده بودجه استفاده می‌شد اصلاح شد. محاسبه بودجه فعلاً روی همه هزینه‌های ثبت‌شده است؛ هنوز بودجه ماه شمسی نیست.
- نمایش/مخفی‌سازی موجودی، دسته‌های پیشنهادی در فرم هزینه، شکل و رنگ هماهنگ مودال‌ها و وضعیت خالی جدید به اپ اضافه شدند.
- کامیت‌ها: `e0b0d67bfaafaf04089568777f909211cafd92d1`، `fad1b35e8d4c90032b728cd21dce82c5a8e9e7a8` و `fa3486638b41f5c7162b07be84570a1dccf9ce23`.
- CI برای آخرین کامیت کد: [Android CI run 45214198775](https://github.com/qashqaeii/Jibak/actions/runs/45214198775) — **success**؛ Unit Tests و `assembleDebug` اجرا و artifact با نام `Jibik-debug-apk` آپلود شد. تست بصری و نصب نسخه تازه روی دستگاه واقعی هنوز انجام نشده‌اند.

## پیشرفت مرحله جدید — Room، WebP، ماه شمسی و تحلیل دسته‌ها

- کد Room نسخه ۱ و DAO به اپ اضافه شد؛ ذخیره تراکنش‌ها به عملیات suspend روی Dispatchers.IO منتقل شده و ذخیره ناموفق به کاربر اعلام می‌شود. انتقال داده قدیمی با تراکنش دیتابیس، شناسه یکتا و بررسی تطبیق کامل رکوردها انجام می‌شود؛ داده قدیمی خودکار پاک نمی‌شود.
- کاراکتر جیبو با فایل `app/src/main/res/drawable-nodpi/jibo_welcome.webp` (حجم ۹٬۸۷۸ بایت) در Welcome، هدر و وضعیت بدون تراکنش استفاده می‌شود؛ خروجی تصویر از لحاظ طراحی برند هنوز به تأیید بصری کاربر نیاز دارد.
- `JalaliMonth.kt` مرز ماه شمسی را با ICU و منطقه زمانی تهران محاسبه می‌کند. درآمد/هزینه داشبورد و مصرف بودجه اکنون برای ماه جاری شمسی نمایش داده می‌شود؛ موجودی ثبت‌شده کماکان حاصل کل سوابق حساب است.
- `MoneyPeriod.kt` درآمد و هزینه دوره را بدون انتقال‌ها محاسبه می‌کند و دسته‌بندی هزینه‌ها را بدون ساخت آمار جعلی تجمیع می‌کند. کارت «خرج‌ها کجا رفتن؟» سه دسته بالای ماه را با نوارهای مقایسه نمایش می‌دهد.
- تست‌های JVM اضافه شد: مرز شروع/پایان دوره، انتقال حساب، جمع دسته‌بندی، دسته خالی و تشخیص سرریز عددی.
- کامیت‌های اصلی: `eda5eedd` (Room import)، `a039f9bc` (WebP integration)، `af36d936` و `ed865a17` (محاسبات و تست‌ها)، `6777ac63` (رفع خطای ICU)، `fd26f239` (داشبورد دسته‌ای).
- آخرین CI کد: [Android CI #45219136419](https://github.com/qashqaeii/Jibak/actions/runs/45219136419) با نتیجه **success**؛ `:core:finance:test` و `:app:assembleDebug` اجرا شدند و artifact با نام `Jibik-debug-apk` آپلود شد. آخرین APK روی دستگاه واقعی، شبیه‌ساز و در تست Android instrumentation هنوز ارزیابی نشده است.

**اولویت بعدی:** تست ارتقای نسخه قبلی و ثبت تراکنش در Room روی دستگاه؛ سپس حساب‌های چندگانه و انتقال واقعی، دسته‌بندی سه‌سطحی، ثبت خرید چندقلمی و پالایش UX مطابق موکاپ. پیش از نسخه تجاری، رمزنگاری، بک‌اند، لایسنس و امضای Release الزامی هستند.

## کارهای باقیمانده به ترتیب اولویت سند مرجع

1. هماهنگ‌کردن قرارداد پول و تاریخ Android با API Django و آماده‌سازی Client شبکه، OTP و Sync push امن.
2. تکمیل دعوت، عضویت، دسترسی، موجودی مشترک و مدیریت تعارض دو دستگاه با تست‌های tenant isolation.
3. تکمیل مدیریت قبوض/اقساط/وام، خرید مشترک، اهداف و گزارش‌ها در Android و Backend.
4. تکمیل سیاست رمزنگاری، خروجی/بازیابی، حذف حساب، امنیت و کارایی در دستگاه واقعی.
5. افزودن AI فقط در موارد کاربردی، مدل Entitlement و تأیید خرید امن بازار، تست پرداخت و Release امضاشده.
6. QA واقعی همه صفحه‌ها روی گوشی و تبلت، تصاویر WebP شفاف، Screenshot QA، سازگاری RTL و انتشار پایلوت.

## معیار تحویل

فایل APK Debug اجرای موفق فعلی در GitHub Actions قابل دانلود است؛ برای بیلدهای آینده نیز فقط پس از موفقیت Workflow باید آن را «آماده» اعلام کرد. APK تولیدی این مرحله Debug است و نسخه امضاشده تجاری محسوب نمی‌شود.

## دستورات CI

Gradle 8.13 و JDK 17 و Android SDK 36:

~~~bash
gradle :core:finance:test :app:assembleDebug
~~~

مسیر artifact در GitHub Actions با نام Jibik-debug-apk خواهد بود (مشروط به موفقیت اجرای Workflow).
