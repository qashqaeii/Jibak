# قرارداد ارتقای بدون حذف داده جیبیک

- شناسه نصب ثابت: `ir.jibik.app`. شماره نسخه فعلی 2 / 0.1.1. هر نسخه توزیعی بعدی باید versionCode بزرگ‌تر داشته باشد.
- نام دیتابیس `jibik_ledger_v1.db` و SharedPreferences `jibik_local_v1` ثابت می‌مانند. Room 20 دارای مسیر مهاجرت 1 تا 20 و بدون fallback مخرب است. این مرحله دیتابیس یا قالب بکاپ را تغییر نمی‌دهد.
- شرط Android برای نصب روی نسخه قبلی: شناسه یکسان، امضای سازگار و versionCode غیرکاهشی. APKهای Debug قبلی از کلید پیش‌فرض محیط CI استفاده می‌کردند؛ تداوم کلید آن‌ها اثبات نشده است. از خود APK یا اثر انگشت، کلید خصوصی قبلی قابل بازیابی نیست.
- برای کانال آزمایشی پایدار، مالک ریپو باید **کلید اصلی همان APK قبلی** را در GitHub Actions secret به نام `JIBIK_UPDATE_KEYSTORE_B64` (فایل keystore با alias استاندارد androiddebugkey و رمزهای استاندارد debug) و اثر انگشت SHA-256 گواهی آن را در repository variable با نام `JIBIK_UPDATE_CERT_SHA256` تنظیم کند. کلید را در Git، چت یا لاگ قرار ندهید. CI هر دو اثر انگشت کلید و APK نهایی را کنترل می‌کند. اگر کلید قدیمی سفارشی باشد، قرارداد امضا قبل از استفاده باید متناسب با همان کلید تنظیم شود.
- در نبود هر دو تنظیم، خروجی `Jibik-debug-apk` صرفاً آزمایشی و فاقد تضمین تداوم امضاست. اگر فقط یکی تنظیم شود یا اثر انگشت متفاوت باشد، build عمداً شکست می‌خورد. خروجی با امضای تأییدشده `Jibik-update-signed-apk` نام دارد. فایل update-identity.txt و checksum کنار APK قرار می‌گیرند. این کانال آزمایشی با امضای تجاری مستقل اشتباه نشود.
- مقایسه APK قبلی و جدید: `apksigner verify --print-certs old.apk` و همان فرمان برای new.apk. اگر گواهی متفاوت باشد، **برنامه قبلی را حذف نکنید**. ابتدا از داخل نسخه نصب‌شده بکاپ کامل رمزدار بگیرید؛ سپس تنها با کلید قبلی یا پس از تأیید امکان بازیابی روی نصب آزمایشی تصمیم بگیرید. نصب با کلید جدید جایگزین مستقیم نیست.
- CI ارتقا جداگانه، APK تاریخی را با کلید مشترک یک‌بارمصرف همان اجرای آزمون و APK جدید می‌سازد، داده آزمایشی در نسخه قبلی وارد می‌کند و با adb install -r بدون حذف یا پاک کردن داده، روی نسخه موجود نصب می‌کند. آزمون با کلید مشترک فقط صحت مسیر نصب و داده را اثبات می‌کند، نه تطابق با امضای گوشی کاربر.
- انتشار عمومی نیازمند تأیید CI، تطابق امضای APK واقعاً نصب‌شده، و تست ارتقا روی گوشی واقعی است.
