# قرارداد ارتقای بدون حذف داده جیبیک

- شناسه نصب ثابت: `ir.jibik.app`. شماره نسخه فعلی 2 / 0.1.1. هر نسخه توزیعی بعدی باید versionCode بزرگ‌تر داشته باشد.
- نام دیتابیس `jibik_ledger_v1.db` و SharedPreferences `jibik_local_v1` ثابت می‌مانند. Room 20 دارای مسیر مهاجرت 1 تا 20 و بدون fallback مخرب است. این مرحله دیتابیس یا قالب بکاپ را تغییر نمی‌دهد.
- شرط Android برای نصب روی نسخه قبلی: شناسه یکسان، امضای سازگار و versionCode غیرکاهشی. APKهای Debug قبلی از کلید پیش‌فرض محیط CI استفاده می‌کردند؛ تداوم کلید آن‌ها اثبات نشده است. از خود APK یا اثر انگشت، کلید خصوصی قبلی قابل بازیابی نیست.
- برای کانال آزمایشی پایدار، مالک ریپو باید **کلید اصلی همان APK قبلی** را در GitHub Actions secret به نام `JIBIK_UPDATE_KEYSTORE_B64` (فایل keystore با alias استاندارد androiddebugkey و رمزهای استاندارد debug) و اثر انگشت SHA-256 گواهی آن را در repository variable با نام `JIBIK_UPDATE_CERT_SHA256` تنظیم کند. کلید را در Git، چت یا لاگ قرار ندهید. CI هر دو اثر انگشت کلید و APK نهایی را کنترل می‌کند. اگر کلید قدیمی سفارشی باشد، قرارداد امضا قبل از استفاده باید متناسب با همان کلید تنظیم شود.
- در نبود هر دو تنظیم، خروجی `Jibik-debug-apk` صرفاً آزمایشی و فاقد تضمین تداوم امضاست. اگر فقط یکی تنظیم شود یا اثر انگشت متفاوت باشد، build عمداً شکست می‌خورد. خروجی با امضای تأییدشده `Jibik-update-signed-apk` نام دارد. فایل update-identity.txt و checksum کنار APK قرار می‌گیرند. این کانال آزمایشی با امضای تجاری مستقل اشتباه نشود.
- مقایسه APK قبلی و جدید: `apksigner verify --print-certs old.apk` و همان فرمان برای new.apk. اگر گواهی متفاوت باشد، **برنامه قبلی را حذف نکنید**. ابتدا از داخل نسخه نصب‌شده بکاپ کامل رمزدار بگیرید؛ سپس تنها با کلید قبلی یا پس از تأیید امکان بازیابی روی نصب آزمایشی تصمیم بگیرید. نصب با کلید جدید جایگزین مستقیم نیست.
- CI ارتقا جداگانه، APK تاریخی را با کلید مشترک یک‌بارمصرف همان اجرای آزمون و APK جدید می‌سازد، داده آزمایشی در نسخه قبلی وارد می‌کند و با adb install -r بدون حذف یا پاک کردن داده، روی نسخه موجود نصب می‌کند. آزمون با کلید مشترک فقط صحت مسیر نصب و داده را اثبات می‌کند، نه تطابق با امضای گوشی کاربر.
- انتشار عمومی نیازمند تأیید CI، تطابق امضای APK واقعاً نصب‌شده، و تست ارتقا روی گوشی واقعی است.

## اصلاح انتشار و بازیابی 0.1.4
- خروجی اصلی و بانکی دیگر با کلید موقت منتشر نمی‌شوند؛ تست‌های CI همچنان اجرا می‌شوند. فقط با گواهی pin شده، خروجی Jibik-update-signed-apk و Jibik-bank-sms-update-signed-apk ایجاد می‌شوند.
- Jibik-recovery-only-apk با شناسه مستقل ir.jibik.app.recovery و نام «جیبیک — بازیابی» کنار برنامه قبلی نصب می‌شود. بدون مجوز SMS؛ داده‌ها کاملاً جدا. این نسخه جایگزین نسخه اصلی نیست. بکاپ رمزدار .jbk نسخه نصب‌شده را در نسخه بازیابی باز و موجودی، تراکنش‌ها، بودجه، اهداف و سلامت دفتر را مقایسه کنید. فایل بکاپ و گذرواژه را خارج از برنامه نگه دارید. تنظیمات بانکی و سایر SharedPreferences لزوماً در بکاپ دفتر مالی نیستند؛ در صورت نیاز دوباره تعریف شوند. نسخه قبلی را تا تأیید کامل حذف نکنید. نسخه بازیابی با امضای موقت نیز ممکن است در اجرای بعد قابل ارتقا نباشد؛ صرفاً ابزار موقت بررسی است.
- ابزار scripts/configure_android_signing.py از روی سیستم مالک با GitHub CLI احراز هویت‌شده اجرا می‌شود. برای ارتقای مستقیم، کلید موجود و اثر انگشت APK نصب‌شده الزامی است. اگر کلید واقعاً گم شده، گزینه --create-new فقط با تصمیم صریح مالک پس از حفظ و تأیید بکاپ، یک کلید دائمی تازه ایجاد می‌کند. کلید خصوصی فقط روی سیستم مالک و GitHub Secret باقی می‌ماند؛ هرگز در کد یا artifact ذخیره نمی‌شود. ابزار هیچ برنامه‌ای را حذف یا نصب نمی‌کند.
- ایجاد کلید جدید، APK قدیمی را قابل جایگزینی نمی‌کند. بعد از تأیید بکاپ در نسخه مستقل و ساخت APK با امضای جدید، انتقال یک‌باره به نصب جدید لازم است. تطابق گواهی با دستگاه و تست CI همچنان ضروری است.

## سیاست فعلی توسعه
تا زمان آماده‌سازی انتشار، APKهای آزمایشی بدون امضای دائمی با نام Jibik-dev-fresh-install-only و Jibik-bank-sms-dev-fresh-install-only قابل دانلود هستند. این خروجی‌ها تضمین نصب روی نسخه قبلی ندارند. خروجی‌های update-signed فقط با کلید ثابت منتشر می‌شوند. نسخه مستقل بازیابی حفظ شده است. انتقال به سرور نیاز به همگام‌سازی معتبر داده دارد و جایگزین امضای ثابت APK نیست؛ قبل از انتشار عمومی هر دو باید تکمیل شوند.

## سیاست جایگزین — نسخه یکپارچه 0.1.5
از این نسخه، Android CI فقط یک artifact نصب به نام Jibik-APK با Jibik.apk، checksum و مشخصات امضا منتشر می‌کند. تمام امکانات موجود نسخه آفلاین، شامل SMS بانکی، در debug اصلی فعال در سطح build هستند؛ پایش همچنان به رضایت، مجوز و معرفی سرشماره نیاز دارد. نسخه مستقل recoveryDebug صرفاً برای ساخت دستی در شرایط بازیابی نگه داشته می‌شود و در CI منتشر نمی‌شود. تنظیم اختیاری امضای ثابت پابرجاست؛ بدون آن فایل توسعه‌ای ممکن است روی نصب قبلی قابل جایگزینی نباشد. اطلاعات و شناسه اصلی ثابت هستند. برای انتشار در فروشگاه، مجوزهای SMS و سیاست‌های توزیع باید جداگانه تأیید شوند.
