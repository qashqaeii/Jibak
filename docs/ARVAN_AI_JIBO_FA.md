# اتصال هوش مصنوعی جیبو به ArvanCloud AIaaS

## مرجع و معماری

الگوی ارتباطی از ریپوی `qashqaeii/TMADS` بررسی و با نیاز مالی جیبیک تطبیق داده شد:

- `TMADS/apps/ai/provider.py`: endpoint امن HTTPS، هدر `Authorization: apikey ...`، مدل، timeout، JSON output، retries محدود، منع redirect، خطای امن بدون نشت کلید
- `TMADS/apps/ai/gateway.py`: fingerprint، کش، سهمیه روزانه، dedupe و قفل پایگاه داده

در جیبیک این معماری در `backend/finance/ai_provider.py` و `backend/finance/ai_assistant.py` استفاده شده و توسعه پیدا کرده است. **دستگاه اندرویدی هرگز به خود Arvan AIaaS وصل نمی‌شود**؛ فقط به API دامنه جیبیک متصل می‌شود. کلید آروان فقط در محیط اجرای سرور ذخیره می‌شود.

## موارد کاربرد در اندروید

- صفحه خانه: «جیبو، همراه مالی هوشمند» / بررسی ترکیب هزینه
- صفحه گزارش مالی: تحلیل هزینه‌های ۳۰ روز گذشته
- صفحه بودجه: راهنمای تعیین بودجه
- صفحه اهداف پس‌انداز: ایده‌های پس‌انداز

همه موارد ابتدا یک خلاصه رایگان **محلی روی گوشی** با داده واقعی ۳۰ روز گذشته نشان می‌دهند. اتصال ابری فقط پس از **ورود به حساب سرور جیبیک** و **رضایت مجزا برای همان تحلیل** فعال می‌شود. در نسخه‌ای که سرور API عمومی در Build Config تعیین نشده، برنامه به‌صورت روشن اعلام می‌کند تحلیل ابری هنوز فعال نیست؛ خلاصه محلی همچنان کار می‌کند.

## اطلاعات مجاز برای ارسال

در API `POST /api/v1/ai/mobile-summary/` تنها موارد زیر پذیرفته می‌شود:

`feature`، `consent: true`، `summary: {period: "rolling_30_days", income_toman, expense_toman, income_count, expense_count, categories: [{code, amount_toman}]}`

کد دسته‌ها از enum محدود است: `food`، `housing`، `transport`، `bills`، `health`، `education`، `shopping`، `entertainment`، `other`. نام دسته سفارشی، نام حساب، شماره تراکنش، یادداشت شخصی، شماره تماس، نام خانواده، نام افراد، ریز قلم‌های خرید و آدرس هرگز در بدنه ارسال نمی‌شود. انتقال‌های داخلی بین حساب‌ها هم درآمد/هزینه حساب نمی‌شوند. مقدار تومانی روی سرور **دقیقاً ×۱۰** به ریال تبدیل می‌شود و نه با Float.

برای اطلاعاتی که قبلاً با مجوز کاربر روی سرور ثبت شده، مسیر مجزای `POST /api/v1/ai/analyze/` با بررسی مالکیت/عضویت خانواده موجود است. این مسیر به دیتابیس سرور تکیه دارد؛ مسیر موبایل بدون نیاز به Sync فعال می‌شود.

## Authentication و ایمنی

- `POST /api/v1/auth/token/`: ورود آزمایشی username/password با **JWT access ۳۰ دقیقه‌ای**. فعلاً کاربر باید از سمت سرور ایجاد شده باشد؛ ثبت‌نام OTP هنوز تکمیل نشده است.
- Android رمز عبور یا JWT را روی دیسک ذخیره نمی‌کند و با بستن دیالوگ فراموش می‌کند. Refresh token صادرشده در پاسخ ورود، در اندروید استفاده/ذخیره نمی‌شود.
- Gateway: سهمیه سراسری و هر کاربر در روز، جلوگیری از درخواست تکراری هم‌زمان، cache پاسخ‌های معتبر تا یک ساعت، خروجی محدود JSON و خطاهای امن.
- توصیه‌ها به‌صورت **advisory-only** هستند؛ هیچ تراکنش، بودجه، حساب، انتقال یا هدف مالی به‌شکل خودکار ایجاد یا ویرایش نمی‌شود.
- پیشنهادهای سرمایه‌گذاری قطعی، تضمین سود و اطلاعات ساختگی در system prompt منع شده‌اند؛ پاسخ همچنان نیازمند قضاوت کاربر است.
- سرور باید HTTPS، احراز هویت معتبر، پایش خطا/هزینه، throttling و نگهداری امن کلید داشته باشد. API تولید بدون این تنظیمات آماده نیست.

## فعال‌سازی (بدون درج کلید در Git)

در محیط **خصوصی سرور جیبیک** و بدون commit یا ثبت در لاگ، تنظیم کنید:

```bash
ARVAN_AI_ENABLED=true
ARVAN_AI_BASE_URL=https://api.arvancloudai.ir/v1
ARVAN_AI_API_KEY=<set-private-runtime-secret>
ARVAN_AI_MODEL=Gemini-2.5-Flash-lite
ARVAN_AI_TIMEOUT_SECONDS=10
ARVAN_AI_USER_DAILY_LIMIT=10
ARVAN_AI_GLOBAL_DAILY_LIMIT=200
```

**مهم:** آدرس پیش‌فرض بالا از نمونه تنظیمات رسمی ریپوی TMADS در همین حساب برداشته شده و در جیبیک نیز تنظیم شده است؛ در صورت تفاوت Endpoint اختصاصی، با مقدار پنل Arvan AIaaS جایگزین شود. داشتن آدرس و کلید به‌تنهایی به معنای تست موفق زنده نیست؛ سرور Django جیبیک نیز باید منتشر شده و مسیر ورود کاربران فعال باشد.

برای build اندروید با آدرس **عمومی API جیبیک (نه آروان)**:

```bash
./gradlew :app:assembleDebug -PJIBIK_API_BASE_URL=https://YOUR-JIBIK-BACKEND-DOMAIN
```

این تنظیم فقط hostname عمومی جیبیک را در APK قرار می‌دهد؛ نه API Key آروان. Build CI بدون این ورودی باید کامپایل شود و تحلیل محلی در APK همچنان فعال باشد.

## وضعیت تست و مراحل باقی‌مانده

- تست‌های سرور: احراز هویت، رضایت، صحت جمع‌ها و دسته‌ها، امن‌بودن aggregate، عدم تغییر ledger، cache و quota، Login JWT.
- تست‌های اندروید: ۳۰ روز واقعی، حذف انتقال‌ها از درآمد/هزینه، ناشناس‌سازی دسته‌ها و حفظ جمع‌های صحیح.
- تست زنده آروان انجام‌شده محسوب نمی‌شود تا کلید محرمانه در محیط اجرا، backend عمومی HTTPS و یک حساب آزمایشی آماده باشند.
- قبل از انتشار نهایی: OTP موبایل، امن‌سازی/مدیریت توکن، فهرست‌سازی حساب ابری، سیاست نگه‌داری نتیجه AI، پایش مصرف سرویس و QA بصری روی گوشی.
